# Repository Guidelines

## Project Structure & Module Organization

Firefly is an Astro 7 blog theme (fork of Fuwari) with Svelte 5 islands. Source lives in `src/`: routes in `src/pages`, layouts in `src/layouts`, UI in `src/components`, styles in `src/styles`, content in `src/content` (`posts`, `dynamic`, `spec`), utilities in `src/utils`, and Markdown/HTML plugins in `src/plugins`. Site behavior is config-driven: features toggle via `src/config/*Config.ts` (barrel-exported from `src/config`) with matching types in `src/types`. There is no `@config` alias — import configs from `@/config`. Static files belong in `public`, source-managed images in `src/assets`, docs in `docs`.

## Build, Test, and Development Commands

Use `pnpm` (enforced by `preinstall`); Node >= 22 (CI uses 24).

- `pnpm dev` / `pnpm start`: Astro dev server.
- `pnpm check`: `astro check`.
- `pnpm type-check`: `tsc --noEmit --isolatedDeclarations`.
- `pnpm lint` / `pnpm format`: Biome check/format with `--write` on `./src`.
- `pnpm build`: full pipeline — LQIPs → `astro build` → font subsetting → Pagefind (output `dist/`).
- `pnpm lqips`: regenerate `src/constants/lqips.json` only (also regenerated by `pnpm build`).
- `pnpm new-post <filename>`: scaffold a post into `src/content/posts/` (filename argument required; Chinese names are slugified to pinyin).
- `pnpm new-dynamic` / `pnpm new-d`: scaffold a microblog entry.
- `pnpm preview`: preview the production build.

CI only runs `pnpm astro check`, `pnpm astro build`, and `biome ci ./src` — not the full build pipeline.

## Architecture Notes

- Content collections are defined in `src/content.config.ts` (repo root, not `src/content/config.ts`); its frontmatter schema is the source of truth for `posts`, `dynamic`, and `spec`.
- Svelte islands handle interactive UI (search, settings, pagination, archive); Swup drives SPA-style page transitions. Translations live in `src/i18n` (`i18nKey.ts` + `languages/*.ts`); primary language is zh_CN.
- Path aliases (tsconfig): `@/` → `./src/`, plus `@components/`, `@assets/`, `@constants/`, `@utils/`, `@i18n/`, `@layouts/`.
- Deployment: GitHub Pages auto-deploy on push to `master` (full `pnpm run build` → `dist/`), plus Vercel (`vercel.json`) and Cloudflare Workers (set `CF_WORKERS` env to select the cloudflare adapter in `astro.config.mjs`).
- `src/constants/lqips.json` and `src/constants/icons-data.json` are generated and committed (Biome-ignored); regenerate LQIPs with `pnpm lqips`. `dist/` is gitignored.

## Coding Style & Naming Conventions

Biome enforces tab indentation and double quotes, with relaxed lint rules for `.svelte`/`.astro`/`.vue` files. Components are `PascalCase` (`PostCard.astro`), config modules `camelCase` ending in `Config.ts`, utilities kebab-case (`date-utils.ts`). Keep `src/types` aligned with `src/config`. Avoid unrelated formatting churn.

## Testing Guidelines

No unit-test framework is configured. Verify with `pnpm check`, `pnpm type-check`, and `pnpm build` for rendering, content, or generated-asset work; use `pnpm dev`/`pnpm preview` with screenshots for UI changes.

## Commit & Pull Request Guidelines

CONTRIBUTING.md and CLAUDE.md request Conventional Commits (`feat:`, `fix:`, `chore:`), though recent fork history uses plain-language Chinese messages. Keep commits and PRs focused on one concern and discuss major features in an issue first.

## Security & Configuration Tips

Never commit secrets or service keys; keep deployment-specific settings in the target platform environment (Vercel/Cloudflare/GitHub Pages). Review regenerated files (`src/constants/lqips.json`, `src/constants/icons-data.json`) before committing.
